# 랭킹 설계 (보류)

2026-10-22 설계만 정리. 아직 구현하지 않음.

## 결정 전 남은 질문

1. 전 세계 랭킹으로 갈지, 브라우저 안 로컬 기록만 둘지
2. 전 세계 랭킹이면 band-note와 같은 Cloudflare 계정에 이 게임용 Worker를 새로 만들지
3. 순위 기준: 도달 웨이브 → 같으면 잡은 말벌 수 (주간·전체 탭을 나눌지)

## 추천안: Cloudflare Worker + D1

GitHub Pages는 정적 파일만 내보내므로 점수를 받을 서버가 따로 필요하다.
이 PC에는 band-note용 wrangler 로그인이 이미 있다.

- Worker 하나 (`/api/scores` GET 목록, POST 제출) + D1 데이터베이스 하나
- 게임(github.io)에서 fetch로 호출하므로 CORS에 `https://rorena15.github.io`만 허용
- 무료 한도: 하루 요청 10만, 저장 5GB. 점수 한 건이 수백 바이트라 사실상 넘지 않음

### 저장하는 값

| 필드 | 설명 |
|---|---|
| nickname | 2~12자, 한글·영문·숫자·밑줄만, 금칙어 거름 |
| wave | 도달 웨이브 |
| kills | 잡은 말벌 수 |
| max_chain | 최대 연쇄 |
| build | 마지막 장착 카드 (`heat8 wave6 ...` 형식) |
| play_sec | 플레이 시간 (검증용) |
| version | 게임 버전 (밸런스가 바뀌면 시즌을 나눌 수 있게) |
| created_at | 제출 시각 |

개인정보는 저장하지 않는다.
IP는 연속 제출 제한에만 쓰고, 솔트를 넣은 해시로 짧게만 보관한다.

### 조작 대응 (완전히 막을 수는 없음)

게임이 브라우저에서 돌아가므로 점수를 지어내서 보낼 수 있다. 서버에서는 비상식적인 값만 거른다.

- 플레이 시간에 비해 웨이브가 너무 높음 (웨이브 하나 최소 몇 초)
- 웨이브에 비해 잡은 말벌 수가 불가능함 (웨이브별 등장 수의 합보다 많음)
- 같은 IP 해시에서 짧은 시간에 연속 제출

### 게임 쪽 작업

- 게임 오버 화면에 닉네임 입력과 제출 버튼 (닉네임은 localStorage에 기억)
- 메뉴에 "랭킹" 버튼과 창 (상위 50, 내 순위 강조)
- 문구는 i18n 사전(`src/i18n.ts`)에 추가
